# v0.3 — Family Hub and platform UX

> **Status:** implementation in progress. Checked items have landed; unchecked items remain.
>
> **Goal:** make Arcadia feel like one coherent family application in daily use. A family member
> should be able to choose their profile, find something, understand whether it is suitable, play or
> save it, return to the same place later, and rate or recommend it without learning which internal
> panel owns each action.
>
> **Release theme:** family continuity, not another D-pad release. v0.2 established a usable
> keyboard/remote baseline. v0.3 fixes navigation defects encountered in the journeys below, but
> does not spend the release retuning spatial geometry across the whole application.

## Product rules

- **The active profile is the owner of personal state.** Favorites, offline saves, ratings,
  playback progress, watch history, recommendations, follows, and notification state must never
  leak between family members.
- **Resume is one concept everywhere.** Home, My Space, title details, episode lists, and the player
  must derive the primary action and displayed progress from the same playback-state rules.
- **Cards have predictable affordances.** Opening the title is the card's main action; resume,
  favorite, save, rate, recommend, and watched state use the same labels, icons, and placement on
  every surface where they appear.
- **Returning means returning.** Closing a detail page or player restores the originating route,
  scroll position, focused card, filters, and search text when that context still exists.
- **The useful state comes first.** Loading, empty, error, and offline states explain what happened
  and offer a relevant next action; they are not blank panels or generic spinners.
- **Motion must earn its cost.** Prefer color, border, and small transforms over blur, large image
  scaling, or layout animation. Honor reduced motion and test the packaged Linux WebKitGTK build,
  not only Chromium.
- **Family safety remains visible at the decision point.** Profile restrictions filter server
  results, while title and playback entry points still show the applicable classification and
  explain why unavailable content is hidden.

## Existing foundation

This release should consolidate what Arcadia already has rather than create parallel systems:

- `/archive` already exposes library, browsing history, calendar, family recommendations,
  notifications, favorites, ratings, offline metadata saves, and a continue-watching response.
- `account_playback_states` already stores per-account movie/episode position, duration,
  watched state, manual overrides, subtitle offset, and update time.
- Global search is already available in the shell and groups results into works, people, studios,
  and planets.
- Accounts already own content policies and personal state. The UI currently calls an account a
  profile in places, but switching still means signing into a different account.

The v0.3 work is therefore mostly information architecture, shared presentation, reliable
navigation state, and playback hardening. New schema/API work should be limited to profile
switching, recent searches if they must roam between devices, and any missing playback context
identified by integration tests.

### Personal activity and privacy

- Recent searches stay on the current device, partitioned by account id, and retain at most eight
  terms. A family member can remove one term or clear their list from the search dialog; switching
  profiles never displays another account's terms.
- Playback activity stays on the family server under the active account because resume must work
  between devices. It is retained until the account, title, or activity row is deleted. Watch
  History provides both per-item deletion and clear-all; deleting an item also deliberately removes
  its resume position and watched override.
- Browsing history remains a separate server-side list with its own clear-all action. Labels never
  call browsing activity “watching.”
- Offline-save intent is account-owned metadata. The device cache is only a replaceable local copy;
  removing the save clears that title's local catalog copy and does not affect another profile.
- **Added this release:** an unauthenticated `/offline` route (linked from the login form, reached
  when no family server is reachable at all — so there is no session to gate anything behind).
  Lists and opens exactly what `saveTitleOffline` (`offline-store.ts`) already cached on that
  device, straight out of IndexedDB, with no network request and no playback (video was never part
  of the offline-save contract). `features/library/offline-library-page.tsx` and
  `offline-title-page.tsx`; `AuthBoundary` treats `/offline*` as public the same way it already
  treats `/login`.
- **Redesigned this release:** the calendar tab's release rows were plain text with no artwork;
  releases are now poster-forward cards (poster, day/month + kind overlaid on the artwork, follow
  action underneath), grouped by month. `releaseCalendarItemSchema` gained `posterPath` (server
  joins the installment's own poster, falling back to the title's).

## Release work

      browser and packaged Tauri/WebKitGTK builds.
- [x] Define one shared work-card view model: title/artwork, classification summary, personal
      state, playable target, progress, and allowed actions. Not a new merged type — `Work`
      (artwork/classification/playable target) plus a personal-state overlay sourced from
      `getLibrary()` (favorite/rating/saved-offline) and `getContinueWatching()` (resume progress),
      both read once per page via TanStack Query's own cache/dedup rather than once per card. See

- [x] Define the resume/up-next ordering rules for films, specials, seasons, completed episodes,

- [x] Separate **watch history** (played movie/episode activity) from the existing **browsing
      history** (titles whose detail page was opened). Keep both only if their labels are explicit.
- [x] Decide and document retention/privacy rules for recent searches and playback activity,
      including clear-one and clear-all behavior.
- [ ] Add test fixtures for at least two adult profiles and one restricted child profile so
      profile isolation is exercised throughout the release.

- [x] Show recommendation sender, reason, age, and accept/defer/dismiss actions without opening a

- [x] Replace the shared text loading state with layout-stable skeletons; give every section a

- [x] Add URL-backed tabs/filters where a family member may expect Back or a shared link to restore

### 2. Profiles and account switching

Arcadia currently models family members as separate accounts. Keep that server-side ownership
model in v0.3; do not introduce a second `profiles` table whose personal state can drift away from
accounts.

- [x] Add an intentional profile chooser for app startup and an avatar switcher in the shell.
- [x] Remember the last active profile per device and start there when policy permits; always make
      switching discoverable.
- [ ] Design a device-scoped switching grant instead of storing passwords or silently sharing the
      owner's session. Adult/privileged profiles require re-authentication or a PIN; a restricted
      child profile cannot switch into a less restricted profile without that gate. **Tried and
      reverted:** a four-digit PIN (`accounts.pinHash`, scrypt-salted) with a Settings → الأمان
      field was built, but nothing ever came to gate switching with it, and in practice each
      family member uses their own device/account — not a shared-device switch flow — so the
      feature was removed rather than left half-wired. Revisit only if a real shared-device need
      shows up; this remains undesigned until then.
- [ ] Make grant expiry, revocation, device naming, and sign-out-all-devices behavior explicit
      before implementing the API or schema.
- [x] Give every profile a strong avatar/accent identity, while preserving contrast and never
      relying on color alone.
- [x] Invalidate or partition account-scoped TanStack Query caches immediately on a switch so the
      previous member's cards cannot flash on screen.
- [x] Refresh visibility-filtered route data after switching and redirect gracefully when the new
      profile cannot access the current title.
- [ ] Rework profile, account, and settings screens around identity, personal preferences, content
      limits, device access, and sign-out; keep family administration in the admin area.
- [x] Present child restrictions in plain Arabic: what is limited, who set it, and how an adult can
      change it. Do not expose hidden-title names through counts, errors, search, or cache.
- [ ] Prove with API and UI tests that favorites, history, ratings, playback, recommendations,
      search history, and offline-save intent remain profile-specific.

## Delivery order

1. **Rules and shared state:** phase 0, account-switching security design, resume contract, and
   route restoration primitive.
2. **Vertical slice:** profile selection → home/My Space continue card → title → player → return.
   Ship this slice behind no duplicate state or temporary profile model.
3. **Hub consolidation:** migrate library, history, ratings, recommendations, calendar, and
   notifications onto shared cards and query rules.
4. **Search and shell:** recent search, profile menu, full restoration coverage, and layer policy.
5. **Hardening:** child-profile isolation, partial failures, WebKitGTK profiling, D-pad closeout,
   and acceptance matrix.

This order makes playback and profile ownership reliable before multiplying their UI across the
hub. It also produces an end-to-end usable improvement before secondary panels are polished.

## Release acceptance

- [ ] On a fresh device, a family member can choose an allowed profile and immediately understand
      what they can resume, what is saved, what family recommended, and what is coming next.
- [ ] Switching profiles changes all personal surfaces without stale data from the previous
      profile, and privileged profiles remain protected.
- [ ] Search from every primary route returns grouped titles, people, studios, and planets, and its
      recent searches belong only to the active profile.
- [ ] Opening a title from a rail/grid/search result and returning restores the same route state,
      scroll position, and card focus.
- [ ] A movie and episodic title resume reliably after player exit and application restart; episode
      completion offers the correct next episode.
- [ ] Classification remains visible before playback, and a restricted profile cannot discover or
      launch disallowed content through search, history, recommendations, direct URLs, or caches.
- [ ] Every primary section has verified loading, empty, partial-error, total-error, and offline
      behavior.
- [ ] The seven primary journeys work with pointer, keyboard, touch-sized controls, and standard
      remote keys at narrow, desktop, and TV-sized viewports.
- [ ] The packaged Linux Tauri/WebKitGTK app completes those journeys without persistent focus
      after pointer use, disruptive animation, or materially worse interaction latency than v0.2.
- [ ] `pnpm check`, relevant unit/API integration tests, `pnpm build`, and the family-journey
      Playwright suite pass.

## Deferred

Full offline video download, a player/backend rewrite, Chromecast, Jellyfin, debrid, Android,
admin-dashboard spatial navigation, broad D-pad geometry retuning, and recommendation algorithms
are not v0.3 work. “Recommendations” in this release means direct suggestions from family members.
The save-offline feature continues to mean cached catalog metadata and artwork until a separate
download release explicitly changes that contract.
