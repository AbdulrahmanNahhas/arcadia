# v0.2 — Lean-back UI and remote navigation

> **Goal:** make Arcadia's family-facing desktop experience comfortable from the couch. Every
> primary journey should work with a keyboard D-pad or a remote that emits standard arrow, Enter,
> and Back/Escape keys. The admin dashboard is outside this release.

> **Accepted baseline:** Abdulrahman validated arrow navigation in the real Linux Tauri app. It is
> useful enough for v0.2, but it is not the final TV-navigation pass: geometric jumps can still feel
> imperfect, complex controls need hand-tuning, and a physical remote has not been certified. Keep
> these limitations visible rather than blocking the rest of v0.2.

## Interaction rules

- Physical arrows follow screen geometry in Arcadia's permanent RTL layout.
- Enter/OK activates the focused control; Back/Escape closes the current layer or returns.
- Focus must always be visible and must scroll into view without abrupt page jumps.
- Text fields, menus, dialogs, and player controls retain their own keyboard behavior.
- Focus motion is short and restrained, and honors `prefers-reduced-motion`.
- Mouse and touch remain supported; spatial navigation is an additional input model.

Spatial navigation lives in React even though desktop is the primary target: React owns the DOM
geometry, focus targets, scrolling, dialogs, and routes. Tauri/Rust is only needed if a physical
remote later produces device events that WebKit does not expose as keyboard events.

## Deferred

True offline video downloads, identifier bulk backfill, Chromecast, Jellyfin, debrid, Android
playback, and admin-dashboard spatial navigation are separate releases. Android/Tauri should reuse
the React spatial-navigation layer when its remote emits standard key events; add a thin platform
adapter only for remote buttons that the WebView does not expose as Arrow/Enter/Escape.
